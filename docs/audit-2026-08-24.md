## Detailed findings

### [P0] Content that can never become visible

- **Location**: `src/lib/components/ScrollReveal.svelte:24–41`
- **Category**: Accessibility / Responsive
- **Impact**: Two distinct failures from one mechanism.

  **(a) Unreachable threshold.** The observer uses `threshold: 0.15`, so an element must have 15% of its own area inside the viewport to reveal. At **320 × 640**, `/about`'s abstract section is **4905px tall in English and 5703px in French**, giving a maximum achievable ratio of **0.130 and 0.112** — both below the threshold. The observer never fires. Measured by scrolling the full page: the section is still at `opacity: 0` at the bottom, in both locales. **On a 320px screen the workshop's core intellectual argument is invisible, on the normal top-to-bottom path, with no workaround.** At 375px French the same section sits at 0.174 — one added paragraph from the same fate.

  **(b) No path for "already passed".** The callback reveals only on `isIntersecting`. An element scrolled past without ever being observed as intersecting is never revealed, and, being above the viewport, never will be. Measured on four ordinary paths:

  | Path                                         | Result                                                |
  | -------------------------------------------- | ----------------------------------------------------- |
  | Reload with browser scroll restoration       | `/call-for-papers`: **9 of 9 sections invisible**     |
  | Back-navigation to a scrolled page           | `/about`: **3 of 3 invisible** — the entire page body |
  | `End` key from the top                       | `/about`: **3 of 3 invisible**                        |
  | `scrollIntoView` (what find-in-page does)    | `/call-for-papers`: **6 of 9 invisible**              |
  | Gradual scroll from the top (the happy path) | 0 invisible, `will-change` released — works correctly |

  A reader who reloads `/about` while scrolled down sees a page with no content in it.

- **Not a regression.** `git log` on the component shows the observer logic is original; the `animate` pass (`c789db7`) restructured the same condition into an early `continue` and changed nothing about when it fires. Every check any pass has run — including Phase 1's, which examined this component's `will-change` handling and praised it — scrolled from the top, which is the one path that works.
- **Recommendation**: reveal on `threshold: 0` and treat "the element's bottom is above the viewport top" as revealed, so a passed element resolves on its first callback. Keep the `will-change` release. The no-JS path (`.js .scroll-reveal`) is already correct and must stay.
- **Suggested command**: `/impeccable harden`

### [P1] `--ink-subtle` fails AA on every raised surface in dark mode

- **Location**: `src/app.css:239` (`--ink-subtle: var(--color-surface-400)` in `.dark`); manifests on `SessionCard.svelte`
- **Category**: Accessibility / Theming · **WCAG 2.2 AA 1.4.3 (Contrast Minimum)**
- **Impact**: `oklch(0.62 0 0)` measures **4.65:1 on the page background and 3.93:1 on `--surface-raised` (#221f1b)**. It passes where most muted text lives and fails where it sits on a card, which is why it survived four passes. axe reports **13 nodes on `/programme`, in both locales, dark only**: every `Social` type label, both excursion descriptions ("Destination to be confirmed", the Teraco description), two excursion end-times, and all three venue links (Decameron, Teraco, Oude Werf). The programme is the highest-traffic page on the site and the one PRODUCT.md says is the product during the event.
- **Not a regression**: the token was set in `8f8d361`, which predates this roadmap. Phase 1 reported zero dark contrast failures on `/fr/programme`, so its scan either measured against the page background or did not reach these rows.
- **Recommendation**: raise the dark `--ink-subtle` to about `oklch(0.66 0 0)` — measured at **4.63:1 on the raised card** and higher on the page, so one token clears both surfaces. Note the neutral (zero-chroma) hue is deliberate and documented at `app.css:60–62` ("the lighter steps are only ever used as text and stay neutral"); only the lightness needs to move.
- **Suggested command**: `/impeccable colorize`

### [P1] The reveal defect also strands `will-change`

- **Location**: same component
- **Category**: Performance
- **Impact**: 8 of 9 elements on `/call-for-papers` keep `will-change: opacity, transform` indefinitely after a jump, each holding a compositor layer for an animation that will never run. Cosmetic next to the invisibility, and it disappears with the same fix. On the normal scroll path the release works exactly as Phase 1 described.
- **Suggested command**: `/impeccable harden` (same fix)

### [P2] Two targets below the 24px floor

- **Location**: `AtAGlance.svelte` (`.stat-link`); `SessionCard.svelte` (`.session-link` author lines)
- **Category**: Accessibility / Responsive · **WCAG 2.2 AA 2.5.8 (Target Size Minimum)**
- **Impact**: the home page's countries figure renders **21.4 × 47px** at 375px and 320px — under the 24px minimum on its narrow axis, and axe flags it. On `/programme`, 11 author links measure 15px tall with **23px of safe clickable space against a required 24** — a 1px shortfall, and the inline-links-in-a-block-of-text exception plausibly covers them, so this is a near-miss rather than a clear violation. The `.session-external` venue links my own probe flagged are **not** violations: axe passes them, they are genuinely inline in flowing text, and their nearest neighbour is 68–115px away.
- **Recommendation**: give `.stat-link` a horizontal padding floor so a two-digit figure clears 24px; step the paper list's `space-y-2.5` to `space-y-3`, which takes the safe space from 23px to 25.
- **Suggested command**: `/impeccable adapt`

### [P3] A 6px legend inside an icon

- **Location**: the PDF download control on `/call-for-papers`
- **Category**: Implementation integrity
- **Impact**: an `aria-hidden` 24×24 SVG contains the literal text "PDF" at **6px**, rendering 8.6 × 5px. It is decorative and the adjacent link names the file, so nothing is lost — but 6px lettering is texture rather than type, well under the documented 11px floor, and it is the only text on the site below that floor.
- **Suggested command**: `/impeccable distill`

### [P3-39] One type literal off the ramp

- **Location**: `src/lib/components/about/ThematicAxis.svelte:61`
- **Category**: Implementation integrity
- **Impact**: `text-[2.75rem]` on the axis numeral (`01`, `02`, …) is the only typographic literal not resolving to a named step. Rendering is correct; the system has a hole in it. The detector's only true finding.
- **Suggested command**: `/impeccable typeset`

## Positive findings

- **Zero horizontal overflow** across all 156 loads — 13 routes × 3 viewports × 2 locales × 2 themes — including 320px in French, which runs ~20% longer.
- **Zero reflow failure at 200% and 400% zoom** on six routes (SC 1.4.4, 1.4.10).
- **Every one of 195 keyboard stops across five routes has a visible 2px focus ring**, no zero-size targets, no traps, no positive `tabindex` anywhere.
- **Semantics are clean sitewide**: exactly one `<h1>` per route, zero heading-level skips, zero missing `alt`, zero unlabelled landmarks.
- **`lang` is correct on all 156 loads** — `en` on every English route, `fr` on every French one, including the client-rendered 404.
- **The map is genuinely lazy**: zero MapLibre requests and **zero external tile requests** before it is scrolled into view. The one external host the site touches is not contacted for readers who never reach the map.
- **One 404 across all routes, and it is the intentional one** — the `/no-such-page` probe. No other console error or warning anywhere.
- Page weight 344–537 KiB uncompressed on every route but `/participants` (846 KiB, of which 300 KiB is 31 lazily-loaded participant photographs — real content, correctly deferred).

## Patterns

1. **Every check anyone has run scrolls from the top.** That is why the reveal defect survived a five-dimension audit, five refinement passes and a polish pass. The failure modes are jump, restore and narrow — none of which a linear read exercises.
2. **A role token can pass on one surface and fail on another.** `--ink-subtle` clears AA on the page and misses it on cards. Contrast was checked per token, not per token-on-surface, so the failing half was invisible to every previous scan.
3. **The measurable dimensions are in good shape and gated.** Performance, theming and integrity all now have CI ceilings — per-chunk JS, per-route blocking CSS, MapLibre, and as of this week images. What remains uncaught is behaviour over time and over paths, which is where both serious findings live.

## Recommended actions

1. **[P0/P1] `/impeccable harden`** — the `ScrollReveal` observer: reveal at `threshold: 0` and treat an already-passed element as revealed, which closes the 320px `/about` invisibility, the four jump paths, and the stranded `will-change` together. This is the gate on Phase 5.
2. **[P1] `/impeccable colorize`** — lift the dark `--ink-subtle` to clear 4.5:1 on `--surface-raised`, and re-check every role token against **both** the page and the raised surface rather than against one.
3. **[P2] `/impeccable adapt`** — the two sub-24px targets: the home countries figure at 375/320, and the programme's 23px inter-author spacing.
4. **[P3] `/impeccable distill`** — the 6px "PDF" legend inside its icon.
5. **[P3] `/impeccable typeset`** — `text-[2.75rem]` onto a named step.
6. **`/impeccable polish`** — a short confirmation pass over whatever the above touch.

**Phase 5 exit criterion is not met** until items 1 and 2 land: the roadmap requires a11y and responsive findings to be zero-or-accepted, and a P0 that can hide a page's entire content is not acceptable three weeks before the workshop.
